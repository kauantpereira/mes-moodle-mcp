# Arquitetura

```
agente (Claude Code / Codex / Gemini CLI)
  ├── skills/ (SKILL.md)            como usar: rotinas e regras
  └── MCP local (stdio) ── src/moodle_mcp/
        ├── núcleo: cliente da API REST do Moodle, tools, avisos, limite de chamadas
        └── perfis/<instituicao>.py  URL, login e regras específicas (isolado; ADR-0009)
              └── API de web services do Moodle (só funções get)
```

## Núcleo
- `client.py`: cliente da API REST. Recebe só URL + token. Só chama funções explicitamente listadas em `FUNCOES_PERMITIDAS`; funções fora da lista são barradas antes da rede. O token vai no corpo do POST. Downloads usam GET separado, limitado ao host do Moodle, com token apenas na requisição. Mensagens brutas, corpos inválidos e detalhes de transporte são descartados.
- `nucleo.py`: ponto usado pelas tools. `url_do_moodle(semestre)` escolhe o Moodle (ADR-0017): o `semestre` pedido, o da sessão (`usar_semestre`), `MOODLE_URL` ou o semestre atual do perfil padrão (`perfis.padrao()`). `cliente(semestre)` reutiliza um cliente por Moodle (URL), todos com o mesmo limitador. Toda tool aceita `semestre` e o repassa a `chamar(..., semestre=...)`. `obter_token` lê `MOODLE_TOKEN` (provisório, tem prioridade) ou o chaveiro. Sem token, `chamar()` faz o login antes (login sob demanda, um só mesmo com tools em paralelo) e continua; `entrar()` refaz o login, confere o token com `core_webservice_get_site_info`, guarda no chaveiro e troca o cliente (mantendo o limite de chamadas). O método é `perfil_para(url).login` ou o genérico. `chamar()` expõe mensagens genéricas sem conteúdo bruto do Moodle, URL ou detalhes de exceção. O transporte HTTP é encerrado por `aclose()` no cliente.
- `login.py`: login genérico (ADR-0016), só API padrão do Moodle. Senha por `login/token.php` (serviço `moodle_mobile_app`, só HTTPS, senha nunca guardada; não é função de web service, fica fora de `FUNCOES_PERMITIDAS`) e fluxo do app (`launch.php` com `passport`, validação do `moodlemobile://token=...`, login manual). Conversa com o aluno por uma `Interacao`: `InteracaoMCP` só manda avisos de progresso e nunca pergunta (sem elicitation; o que precisa de resposta devolve o comando de terminal); `InteracaoTerminal` pergunta, com senha e link lidos sem eco. Contrato de `Perfil.login`: `async (base_url, interacao) -> token`, levantando `LoginFalhou`.
- `chaveiro.py`: token no chaveiro do sistema (`keyring`), chave = URL base do Moodle; sem chaveiro, `ler`/`salvar` não levantam erro e o token fica só na memória.
- `server.py`: `ServidorMoodle` (um `MCPServer` que passa o contexto da tool ao núcleo, para o login sob demanda mandar avisos de progresso) e as tools `entrar` e `usar_semestre`.
- `navegador.py`: captura do token pelo navegador no fluxo do app, com Playwright (ADR-0016). Genérico, usado por perfis com SSO: Chrome → Edge → Chromium do Playwright (download avisado) → login manual (pelo chat, vira o comando `moodle-mcp entrar --manual`). Intercepta a resposta do `launch.php`, fecha a janela ao achar o `moodlemobile://token=...` e manda progresso enquanto espera (até 10 min). Nenhuma URL, cookie ou token é registrado; o download do Chromium descarta a saída (o stdout é o canal do MCP).
- `cli.py`: `moodle-mcp entrar` (`--manual` força o login manual) / `moodle-mcp sair`, com `--url` e `--semestre`. Único lugar em que o aluno digita senha ou link; mesmo login e mesmo chaveiro do servidor.
- `limite.py`: contador e limite de chamadas (ADR-0005). Janelas deslizantes, padrão de 60 chamadas por minuto e 600 por hora; `call()` e `baixar()` registram antes da rede, e a recusa vira `ToolError` com o tempo de espera. O contador é por processo: sessões simultâneas contam separado.
- `cache.py`: cache curto em memória (ADR-0005). `core_enrol_get_users_courses` e `core_course_get_contents` valem 5 min; chave = função + parâmetros já achatados. `call()` consulta o cache antes do limitador: um acerto não sai para a rede nem conta no limite. Só respostas de sucesso entram; erros do Moodle e de HTTP não. Cada leitura devolve uma cópia; teto de 128 entradas (sai a mais antiga). Relógio injetável, como em `limite.py`. Também é por processo.
- `manutencao.py`: janela de manutenção (ADR-0005, ADR-0009). O cliente pega `perfil_para(base_url).janelas_manutencao` e, dentro de uma janela (horário no `perfil.fuso`; janela com início > fim cruza a meia-noite; início = fim é vazia), `call()` e `baixar()` levantam `EmManutencao` antes do limitador e da rede. `chamar()` traduz para `ToolError` com a janela e o horário para tentar de novo, sem token nem URL. Respostas já no cache curto continuam valendo durante a janela. O `GENERICO` não tem janela; os horários de cada instituição ficam no seu perfil. Fuso desconhecido cai em UTC (com aviso no log). Relógio injetável.

## Perfis (`perfis/`)
- `perfis/__init__.py`: contrato `Perfil` (hosts, fuso, janelas de manutenção, login próprio no contrato de `login.py`, `url_do_semestre` para Moodle por semestre), `perfil_para(base_url)` e `padrao()` (o único perfil que sabe montar a URL, usado sem `MOODLE_URL`). Cada instituição é um módulo `perfis/<inst>.py` com `PERFIL = Perfil(...)`, descoberto sozinho; sem módulo (ou com o PR revertido), vale o `GENERICO`. O núcleo nunca importa um perfil pelo nome (ADR-0009).
- `perfis/ufmg.py`: host `virtual.ufmg.br`, um Moodle por semestre (`/AAAAS`; perfil padrão sem `MOODLE_URL`, com o semestre atual pela data: janeiro a junho → 1º, julho a dezembro → 2º; aceita `2026.1`, `20261`, `anterior`, `atual`), fuso `America/Sao_Paulo`, janela de backup 01h30–06h00 (ADR-0005) e login pelo navegador (SSO minhaUFMG). O perfil entrou na `main` junto com o limite de chamadas, no squash do #92 (o PR próprio, #102, foi mergeado na branch de baixo), então não há um commit só dele para `git revert`. Para reverter, apague `perfis/ufmg.py`, `navegador.py` e `tests/test_perfil_ufmg.py` e tire o `playwright` do `pyproject.toml` (`uv lock` atualiza o `uv.lock`); o Moodle da UFMG passa ao login genérico (senha ou manual, pelo terminal). A lista completa do que o perfil trouxe está nos arquivos do #102.

Decisões: ver [adr/](adr/).
